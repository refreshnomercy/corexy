# page0 / p0 实际位置绿圈

STM32端已经实现双电机编码器实际位置回传。屏幕端请在USART HMI编辑器中按下述步骤修改现有工程，编译并下载。`1.HMI`为用户维护的屏幕工程，本次没有改写它。

红色实心点表示最后一次点击，绿色空心圈表示最近一次有效的实际位置。到位后绿圈包住红点。红点只代表点击记录：运动中只保留最后一个待执行目标，中间点击不一定执行。

用户反馈整图刷新时明显闪烁，当前事件已改为局部恢复底图、坐标不变不重画。若已配置过最初的12个变量，请按[闪烁修正说明](MARKER_FLICKER_FIX.md)只增加7个变量并替换两个事件；STM32 HEX沿用原版。

## 1. 在page0配置19个“变量”控件

变量均选择数值类型，属性通过`.val`访问。名称必须完全一致，不是可见的数字显示控件。

| objname | vscope | 初值val | 用途 |
|---|---|---:|---|
| gpx | 全局 | 0 | MCU收到的实际屏幕X像素 |
| gpy | 全局 | 0 | MCU收到的实际屏幕Y像素 |
| gok | 全局 | 0 | 实际位置有效标志 |
| gnew | 全局 | 0 | 完整快照提交标志 |
| dpx | 私有 | 0 | 已提交绿圈X |
| dpy | 私有 | 0 | 已提交绿圈Y |
| dok | 私有 | 0 | 已提交绿圈有效标志 |
| rpx | 私有 | 0 | 最新红点X |
| rpy | 私有 | 0 | 最新红点Y |
| rok | 私有 | 0 | 是否已有点击 |
| gage | 私有 | 1000 | 未收到完整快照的时间ms |
| paint | 私有 | 1 | 需要重画画布 |
| brx | 私有 | 0 | 上一帧红点X |
| bry | 私有 | 0 | 上一帧红点Y |
| brok | 私有 | 0 | 上一帧是否有红点 |
| ex | 私有 | 0 | 恢复块屏幕X/临时变化标志 |
| ey | 私有 | 0 | 恢复块屏幕Y |
| ix | 私有 | 0 | 恢复块原图片X |
| iy | 私有 | 0 | 恢复块原图片Y |

四个g变量必须设为全局，MCU发送`page0.gpx.val=...`等指令。在途包即使遇到页面切换，也只更新page0的变量，不在新页面画圆。

## 2. 在page0新增一个定时器tmPos

设置`objname=tmPos`、`tim=100`（ms）、`en=1`。将[tmPos_timer.txt](events/tmPos_timer.txt)完整粘贴到定时事件。

定时器负责统一画图：仅在位置/有效性变化或点击时，用xpic恢复旧标记下面的9×9/13×13原图，再画最新红点和绿圈。重复位置回传只清通信计时，不绘图。当前事件不再反复ref p0/doevents。不要在其他定时器里刷新p0或整页，否则会擦掉标记。gnew只有最后一条命令才置1；绘图使用d变量，避免半包坐标或点击事件造成X/Y混用。

本局部恢复脚本要求p0为位于(20,20)、按原尺寸显示470×420图片资源的普通图片控件；整屏切图或缩放图需要调整来源坐标。细节见闪烁修正说明。

连续1秒没有完整回传时，绿圈自动隐藏，红点保留。自检仍为阻塞过程，期间停止位置回传，不能将绿圈理解为实时显示自检中的运动。

## 3. 替换m0按下事件

把原来的按下事件替换为[m0_press.txt](events/m0_press.txt)。原坐标帧保持9字节小端格式，真实点击坐标先发送，再对红点显示位置作边缘限制。

该事件只记录红点并请求重画；实际重画集中在tmPos，最多约100ms后可见。删除原事件里的`ref p0`、`doevents`和`cirs`，避免两个流程互相擦除。弹起事件不要再发送一次相同坐标。

## 4. 配置page0后初始化事件

将[page0_postinit.txt](events/page0_postinit.txt)加入page0的“后初始化事件”。若已有页面初始化代码，保留原有业务代码并合并这些赋值；不要重复放入旧绘图/发坐标代码。

每次进入page0重置红点和绿圈及上一帧状态，立即请求当前实际位置。绘图不写在前初始化事件中。保持p0在下、m0在上；p0须覆盖整个热区，若有加载特效应选择立即加载/无特效。

## 5. 编译、下载及上板验收

1. 在USART HMI编辑器编译并下载修改后的屏幕工程。屏幕波特率仍115200、8N1，使用普通指令解析（recmod=0）。
2. STM32烧录`../MDK-ARM/corexy/corexy_HMI_GREEN_POSITION_LINE20_P30_R15_CUR200.hex`。
3. 蓝牙启动新增`HMI ACTUAL MARKER: request 55 50 01, encoder feedback, 100ms`。
4. 未自检：点击显示红点，绿圈隐藏，电机不运动。
5. KEY1自检完成：绿圈应出现在左下角附近。点击内部位置，红点立即更新（最多100ms）；绿圈随滑块沿两点连线移动，到位后包住红点。
6. 运动中连续点两处：红点显示最后一次点击，绿圈继续表示正在运动的实际位置；当前任务结束后执行最后一次点击。
7. 蓝牙S/故障撤销标定时，绿圈隐藏且待执行目标清除；KEY1重新自检后恢复显示。切换页面停止取样请求，返回page0重建标记。
8. 可在屏幕调试中停止位置请求或断开MCU至屏幕的TX线：1秒后绿圈隐藏，红点保留。

变量缺失或名称不对时屏幕会返回无效变量错误。先确认四个g变量的全局属性、page0名称及tmPos是否启用。

## 坐标、刷新和协议

热区仍`x=20,y=20,w=470,h=420`，真实像素X=20..489、Y=20..439。每次自检的软限位用于映射：

```text
px = 20 + round(actual_x / x_max * 469)
py = 439 - round(actual_y / y_max * 419)
```

actual_x/y来自0x36双电机累计编码器反馈，不能用`corexy_get_pos()`的命令模型替代。只有有效标定、双轴均收到过位置包且年龄≤300ms、未故障，才发送有效绿圈。实际位置超出软限位0.5mm以上也不显示。

圆心在画布边缘向内限制到X=26..483、Y=26..433，确保半径6的绿圈及红点都能被p0完整擦除。该限制仅用于画图，不改变坐标帧、实际坐标、软限位或定位终点。

屏幕每100ms发送位置取样请求：

```text
55 50 01 FF FF FF
```

STM32每100ms最多回传一包，全部使用正常ASCII指令，每条追加三个0xFF：

```text
page0.gnew.val=0
page0.gpx.val=255
page0.gpy.val=229
page0.gok.val=1
page0.gnew.val=1
```

上例对应161×144mm范围内的实际中心(80.5,72)mm；gok=0时隐藏绿圈。没有新UI请求时不向旧屏幕发送这些命令。UART发送忙时只保留一个请求，完成后重新取最新反馈，不积压旧位置。

MCU回传周期100ms，屏幕定时处理周期100ms，典型显示延迟约100~200ms（还需计入反馈和图片刷新），不是到位判据。图上重叠不代表精确到位，仍以固件编码器验收与POS DONE为准。

固件编译0错误0警告；84项运动/显示、50项屏幕收发、36项自检、19项CAN测试通过，共189项。测试覆盖实际生产C与模拟驱动、UART缓冲所有权及完整回传协议；屏幕脚本仍需在编辑器编译下载，并完成上述实机验收。
