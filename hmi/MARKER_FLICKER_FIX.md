# 红点和绿圈局部刷新

上一版tmPos每收到完整回传就`ref p0`、`doevents`，每100ms整张470×420底图先擦再画，即使坐标没变化也执行。该路径会反复擦掉红点和绿圈，能解释用户报告的明显闪烁。

新脚本只在显示坐标/有效性变化或新点击时绘图：从p0的原图片恢复旧红点下9×9像素、旧绿圈下13×13像素，再画当前标记。静止位置的重复回传只维护通信计时，不重画。绿圈移过红点时会重画红点，防止互相擦掉。

## 在编辑器中的修改

1. 保留原来的12个变量，在page0再增加7个**数值变量**，全部设为**私有**、val=0：

| objname | 用途 |
|---|---|
| brx | 上一帧已经画出的红点X |
| bry | 上一帧已经画出的红点Y |
| brok | 上一帧是否画了红点 |
| ex | 恢复小块底图的屏幕X/临时变化标志 |
| ey | 恢复小块底图的屏幕Y |
| ix | 对应原图片内的X |
| iy | 对应原图片内的Y |

2. 用[tmPos_timer.txt](events/tmPos_timer.txt)完整替换tmPos的定时事件，`tim=100`、`en=1`保持原值。
3. 合并更新后的[page0_postinit.txt](events/page0_postinit.txt)到page0后初始化事件；保留其他原有初始化内容。新增的7行也必须加入。
4. m0按下事件继续使用[原坐标/红点事件](events/m0_press.txt)，无需更改。STM32继续使用原绿圈版HEX，无需重新烧录。
5. 屏幕编译并下载。删除其他定时器或触摸事件里反复执行的`ref p0`/整页刷新。单纯去掉旧脚本的doevents会重现绿圈被底图覆盖，不能作为解决办法。

## 底图要求

本脚本沿用当前热区与同尺寸图片：p0位于(20,20)，原图片资源为470×420像素，按原尺寸显示，画布上方只有透明热区m0。`p0.pic`是原图片资源ID；`p0.id`是控件ID，两者不同。

局部恢复指令：

```text
ex.val=dpx.val-6
ey.val=dpy.val-6
ix.val=ex.val-p0.x
iy.val=ey.val-p0.y
xpic ex.val,ey.val,13,13,ix.val,iy.val,p0.pic
```

前两个坐标是屏幕目标位置，后两个坐标是原图片内部位置。采用xpic以保留网格/图片纹理，不用单色填充擦除。若p0使用整屏切图、缩放图片，或图片资源尺寸与热区不同，需要先按实际资源调整来源坐标，不能直接套用。

恢复块均在热区内，因为标记圆心仍限制到X=26..483、Y=26..433。图上边缘圆心的限制只影响绘图，不影响真实目标或编码器坐标。

其他组件若覆盖画布，恢复底图也可能擦掉它们，应将状态文本、按钮放在画布外。若有“清除痕迹”按钮，其事件应设`rok.val=0`、`paint.val=1`，不要反复重绘整张p0；绿圈会保留。

## 验收

- 静止时：连续重复回传不再执行绘图，红点/绿圈保持显示。
- 移动时：绿圈跟随，只恢复上一圈的小区域；旧圈不残留，红点保留。
- 连续点击：旧红点的小区域恢复，新红点出现，待执行目标逻辑保持原值。
- 绿圈与红点重叠、分离或交叉：两者都可见，无纹理被单色抹掉。
- MCU反馈失效/故障，或1秒没有完整回传：旧绿圈被局部清除，红点保留。
- 四角：无恢复块越出底图或读取原图片外区域。

该方案显著减少擦除面积与重画次数，但不是整屏双缓冲，不承诺所有型号绝对无闪烁。仍需在编辑器编译及实际屏幕上观察移动时的效果。
